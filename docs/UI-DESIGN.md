# 界面设计规范（UI-DESIGN）

能力中心界面的设计原则与各页面规格。改界面前先读本文；组件 API 见 [CLIENT-GUIDE.md](CLIENT-GUIDE.md) 第 10 节（kit），宿主组件与主题变量见 [PRIMITIVES.md](PRIMITIVES.md)。

## 0. 原则（取舍时以此为准）
1. **安静**：层级靠字号、字重、灰度，不靠颜色；默认画面几乎全是中性灰。
2. **一处一事**：每一行只回答「这是什么、开没开」，其余信息进详情。
3. **只在需要时出现**：状态标记、横幅、悬停操作只在有事时出现；一切正常时画面上没有它们。
4. **一个强调色**：DSH 主题强调色只用于主按钮、「可更新」、活跃状态点；红色只表示错误，琥珀色只表示连接中或警告；不用绿色。
5. **不随手删功能**：界面改版时 DECISIONS 中的能力保留，只是换位置；要删功能先改 DECISIONS（0.7.0 按使用者的决定删了 MCP 的表单、预设、导入、「运行中」与全局设置页）。

## 1. 视觉语言（全部映射到 DSH 主题变量，禁止写死颜色）
- 间距 4 / 8 / 12 / 16 / 24；圆角：容器 10px，控件 6px。
- 字号：页面标题 18/600；分组标签 12/500 次要色；行标题 14/500；行副标题 12.5/400、单行截断，颜色比次要色再弱一级但须满足 WCAG AA（4.5:1）；路径与命令用 DSH 代码字体（`--ds-font-family-code`），12px。
- 列表：一个圆角面板，行与行之间 1px 细分隔线，不给每行套卡片。
- 行：最小高度 52px，内容垂直居中；悬停背景提亮一级、行尾出现淡色「›」；整行可点击打开详情，Tab 聚焦、Enter 打开。未悬停时每行最多一个可见控件（开关）。
- 状态点：灰 = 空闲，强调色 = 活跃，红 = 失败，琥珀 = 连接中（kit 保留该组件；0.9.0 起 MCP 页不显示运行状态，暂时没有页面用它）。
- 标记：小号描边胶囊 11/500，tone 为 neutral / accent / warn / danger，每行最多 2 个。
- 详情抽屉：右侧滑出，宽 560px（宽内容 720–920px，窄屏 100%），Esc 与遮罩可关闭，关闭后焦点回到原行；头部为标题、单行截断的副标题与开关；底部只在有操作时出现，危险操作放最左，用弱化的红色文字按钮。
- 开关：在能力中心作用域内缩到宿主尺寸的约 80%，颜色保持 DSH 原生。
- 加载用 6 行骨架屏；空状态 = 一句标题 + 一句说明 + 一个按钮。
- 不放常驻的解释性长句；必要说明进工具提示或详情。
- 重复出现在每一行的信息要么不显示、要么调淡：只在有区别时才显示（例如目录标签），常见的默认值用最弱的说明色、例外用正常次要色（例如调用权限）。
- 输入框占位文字用次要色（宿主默认太淡）；数量为 0 的「需关注 / 有错误」分段调淡，有问题时恢复正常。
- 页头与正文最大宽度 1180px（左对齐），宽屏时描述不被拉得过长。

## 2. 外壳
- 页头：「能力中心」+ 右上角「ⓘ」（诊断信息模态框）；下方是下划线式标签。**0.9.0 起标签栏没有红点**：原先只有 MCP 页用它上报连接失败，运行状态界面去掉后这条通道一并删除；连接失败只看 health 的 `mcpServers`。
- 页面上不放诊断卡片；模块降级或 MCP 运行时退回桩时，页头下方出现 warn 横幅「部分功能不可用：<模块>」+「查看详情」。
- 插件升级后没重启 DSH（浏览器半已是新版本、宿主半还是旧的）时，页头下方出现 warn 横幅「能力中心已升级到 x，但 DSH 还在运行 y 的宿主代码；重启 DSH 后新功能才能用」；新接口 404 时的报错也给同样的提示。
- 标签切换保留各自的搜索、筛选、滚动位置（标签隐藏而不卸载）。

## 3. 当前版本（0.10.0；网络访问改为「直连 → 镜像 → 缓存」三级，见 D-B19）
页面有三个标签：**提示词 / 技能 / MCP**（顺序即此顺序）。**打开能力中心默认停在「提示词」**（0.9.0 起；0.8.0 之前默认技能）。插件管理页本插件那一行的「配置」直达 MCP。

- **技能**：工具栏 = 搜索、筛选（全部 / 模型可调用 / 模型不可调用 / 需关注）、主按钮「添加技能」、「⋯」（检查全部更新、全部更新、GitHub 镜像…、回收站）。没有目录下拉（使用者决定）：目录标签照旧只在行上出现。
  - 列表两级折叠（D-B14）：一级 = 层级 **DSH 内置**（默认折叠，标「只读」）/ **用户级** / **项目级**，标题行显示技能数；自定义技能目录归用户级，位于 DSH 安装目录（app.asar）里的归 DSH 内置；没有当前工作区时项目级只有一行说明。二级 = 来源仓库 `owner/name`（名称排序，「无来源」最后）；DSH 内置不细分；某层级全是无来源、或来源数据不可用时直接列技能。折叠头是整条按钮（Tab 聚焦、Enter / Space 切换）。
  - 行 = 名称 + 淡色「目录」标签（技能目录路径里 skills 前一段，如 `.agents`；等宽小字、无边框、不算标记，悬停给完整路径；只在该层级的技能来自不止一个目录时显示）+ 描述 + 标记（不可加载 / 可更新 / 被遮蔽）+ 调用权限文字 + 开关。调用权限（D-B17）是开关左侧一小段文字，固定宽度右对齐成一列：「模型、用户 / 仅模型 / 仅用户 / 不可调用」，默认的「模型、用户」用最弱的说明色、例外用次要色；悬停说明两种调用各自的来源；开关管的是模型调用，用户调用只读。只读技能（DSH 内置、只读的自定义目录）不显示开关（禁用的开关会被看成「已关闭」），留同宽空位让文字仍对齐。
  - 筛选口径：后两段筛的就是行右侧开关管的那件事（`disable-model-invocation`，D-B3 / D-B17），所以叫「模型可调用 / 模型不可调用」，开关的悬停与启停 Toast 用同一套说法；「需关注」= 不可加载 + 被遮蔽 + 可更新。**0.8.0（D-B4）**：不可加载与被遮蔽的技能（DSH 不会加载）默认不显示，「全部 / 模型可调用 / 模型不可调用」与搜索都不出现它们，只在「需关注」里看得到；这三段的计数、分组标题的技能数都只数显示出来的，某个层级或来源仓库里的技能全被隐藏时按空处理；当前不在「需关注」而又有被隐藏的技能时，列表底部加一句「另有 N 个技能 DSH 不会加载（不可加载或被遮蔽）」+ 文字按钮「查看」（切到「需关注」）。搜索或任何筛选生效时有匹配的分组自动展开、无匹配的隐藏；筛选中仍可手动折叠（只对这一次筛选有效，换一种筛选又全部展开），清空后回到原来的折叠状态。
  - 详情抽屉：概览 → 体检 → 来源与更新 → 文件 → SKILL.md（默认折叠）；底部删除（区分「目录」与「文件」）。另有回收站抽屉。
  - 「⋯ → GitHub 镜像…」对话框（D-B18）：一句说明（镜像只用于从 GitHub **下载**技能文件；检查更新走 GitHub 接口、不经过镜像；镜像能看到并改动下载内容，只用信任的镜像，且走镜像时不发送 GitHub 令牌）+ 输入框（占位 `https://ghfast.top/`，打开时填入当前值，留空保存 = 清除）+「测试」（显示「可用 · N 毫秒」或宿主给的中文原因）/「保存」/「取消」。**0.10.0（D-B19）**：输入框下方常驻两行网络状态——「直连：可用 / HTTP 403 / 超时（原因）」（网络层失败才把中文原因括在括号里；没探测过就整行不出现）与「镜像：下载 ✓ · API ✗」（下载与 API 分别判定，未知的那项写「未探测」；没配置镜像写「未配置」；整条镜像不可用时括号里给中文原因）。两行来自 GET skills/settings 里上一次探测的结果，点「测试」后按这次的 direct / mirror 刷新（宿主没给的那一路保留上一次结论）；网络问题只写在这两行，不弹错误横幅。已设置时菜单标签带上镜像主机名（例如「GitHub 镜像：ghfast.top」）；保存成功走 Toast（清空时说明改回直连 GitHub），保存失败（422）把宿主的中文 message 显示在对话框里且不关闭。
- **添加技能 = 仓库视图**（D-B16，宽抽屉 860px），自上而下：
  - 一个输入框（D-B16，0.3.4）：内容像仓库地址（owner/name、GitHub 链接，可带 /tree/<分支>/<子目录>）时，右侧出现分支输入与「浏览」（临时只看这一个仓库，可直接装）「加入仓库列表」；否则是「搜索 skills.sh」，Enter 同样生效。搜索结果先是一行「搜到 n 个结果 · 收起 / 展开」，下面约 4 行高的滚动框，结果行悬停「浏览」「加入仓库列表」，已在列表的标「已在列表」；从结果里浏览或加入后自动收起。**0.10.0（D-B19）**：那一行摘要后面跟一句来源小字——联网失败但拿到缓存时「缓存于 2026-01-02 03:04」（宿主照常返回结果，界面**不弹错误横幅**，结果照常列出），经镜像时「经镜像 ghfast.top」，直连不显示（安静）；时间缺失或解析不了只写「缓存结果」。临时浏览的结果与安装反馈出现在输入框正下方并自动滚到可见，「返回汇总」回来。
  - 仓库列表（默认折叠成一行「仓库列表 · n 个」）：行 = 仓库名（预置的标「预置」）+「分支 · 子目录 · n 个技能 / 扫描失败：原因 / 未扫描」；悬停浏览 / 编辑 / 移除，编辑就地展开分支与子目录。
  - 汇总发现：工具栏 = 搜索、全部 / 未安装 / 已安装（带数）、仓库下拉、「上次扫描：x 分钟前」与「刷新」。按仓库分组折叠（0.3.4）：分组标题 = 仓库名 + 等宽「@分支」+ 技能数，技能数超过 50 的仓库默认折叠；搜索或筛选时有匹配的分组先全部展开、仍可手动折叠。行 = 勾选框（唯一可见控件）+ 名称 + 描述 + 「已安装」。结果缓存在插件数据目录，打开先显示缓存；第一次没有缓存时自动扫一次，之后只有「刷新」才联网；加入、修改仓库只补扫该仓库，移除仓库同时删掉它的结果；每组每批渲染 200 行，组下「再显示」。
  - 底部（有勾选时才出现）：安装位置（`~/.agents/skills` 默认、`~/.dsh/skills`、当前项目）+ 已选数 +「安装选中技能」；跨仓库的勾选按仓库分组依次安装，结果逐项列在下方。
- **MCP**（0.7.0；**0.9.0 起不显示运行状态**）：工具栏 = 搜索、筛选（全部 / 已启用 / 已停用）、「添加服务器」（两种方式：粘贴 JSON 与从 Official Registry 搜索，见下）；每台服务器只用 JSON 编辑（D-C2 / D-C3），表单、预设模板、从 Claude Code / Codex 导入都已删除，「⋯」里的全局设置页也删除。行 = 名称 + 等宽摘要「程序名 参数」（路径只留文件名，如 `node fake-mcp-server.mjs`；完整命令在悬停提示与详情里）+ 开关，悬停出现拖动把手。详情抽屉 = 概览 → **进程**（0.9.3 起：「全局一份 / 按会话」两段控件 + 一句说明，切换即保存；仍走既有 upsert，不新增接口）→ 环境变量与请求头。
  - 详情抽屉：概览 → 环境变量与请求头（遮罩、显示）；底部删除｜JSON 编辑。
  - **「添加服务器」对话框的两种方式**（0.9.0）：顶部一个分段切换「粘贴 JSON」（默认，行为不变）/「从 Official Registry 搜索」。两个面板都常驻（切换只切 hidden），切到另一种方式再切回来，**粘贴的 JSON 与它的解析结果都还在**。
    - 搜索态：输入框（回车也搜索）+「搜索」。registry 的 search 实测很慢（jira 约 14 秒、filesystem 超过 60 秒），所以请求期间按钮显示「加载中…」并禁用，旁边一行小字「正在搜索 Official Registry，可能要 10–60 秒…」；失败时显示宿主给的中文错误 +「重试」，宿主把超时也写成中文，同样走这条路。
    - 结果态：一行「搜到 n 个结果」+ 一个**固定高度（约 6 行）内部滚动**的列表面板（结果再多也不会把对话框撑破；整个面板另有约 72vh 的限高并可滚动，预览里的 env 表单与配置 JSON 因此始终够得到）；行 = 展示名（没有就用 registry 名）+ 等宽小字「registry 名 · 版本」+ 接入方式标记（远程 HTTP / npm 包 / PyPI 包 / OCI 镜像，每行最多 2 个）+ 行尾「需要填 n 个变量」（0 个时不显示）。有下一页时面板下方一行「加载更多」。搜不到 = 一句「没有匹配的服务器，换个关键词再试」。
      **0.10.0（D-B19）**：「搜到 n 个结果」下面一行来源小字——超时 / 429 / 5xx 但同一关键词有缓存时，宿主照常返回缓存的条目并在响应里带 `provenance.route = "cache"`，界面显示「缓存于 2026-01-02 03:04 · 点「重试」刷新」并在同一行给一个「重试」（重新问一次第一页），**不弹错误横幅**；经镜像时「经镜像 <主机名>」；直连不显示。时间缺失或解析不了只写「缓存结果 · 点「重试」刷新」。
    - 预览态：点一行调详情（约 2 秒）。头部是展示名、等宽 registry 名、版本与接入方式，下面是 notes 原文（逐条列表），左上角「返回搜索结果」回列表。
      - 能生成：可编辑的**服务器名**（默认 = 宿主建议名，校验 `[A-Za-z0-9_-]{1,32}`；与本配置里已有服务器重名时即时标红）+ 逐个**环境变量**输入（必填的标「必填」、空着就标红并不许保存；可选的标「可选」，空着不挡保存）+ 只读等宽 JSON（落盘形态，随名字与变量实时更新，就是提交给 upsert 的那一份）+「保存」。
      - 不能生成：一条 warn 横幅说明原因（宿主给的中文），**没有保存按钮**，也没有名字与环境变量表单。
    - 保存仍走既有的 `POST mcp/servers/upsert`（服务器名用输入框的值覆盖建议名）。成功留一行「已保存「x」。」并锁住保存按钮（再改名或改变量才解锁）；同名冲突（宿主 409）显示「服务器名「x」已经存在（宿主返回 409），换一个名字再保存」；其他失败显示宿主的中文 message 与逐字段错误。
  - 页面底部不再有「运行中」区域（D-E1，0.7.0 删除）。**0.9.0 起连运行状态也不显示**：行上没有状态点、「已连接 · N 个工具」与失败标记，抽屉里没有「工具」一节与「重新连接」，筛选里也没有「有错误」。挂载照常（服务器仍由官方 MCP 插件连接）。
  - **失败提示（0.9.1）**：有服务器连接失败时，工具栏下方出现一条 warn 横幅「连接失败：<名字>（<原因>）。连接由 DSH 官方 MCP 插件负责，重启 DSH 会重试；详情见 GET health 的 mcpServers。」只提示失败，不显示工具数、不提供重连；多条失败时列出名字（原因只在只有一台时显示）。进页面读一次 health，配置一变再读一次，仍在 `connecting` 时每秒补读、最多 10 次。
- **提示词**（0.8.0）：管理 DSH 会加载的 AGENTS.md / CLAUDE.md——全局 `~/.dsh/AGENTS.md`，加上当前会话工作区从项目根到工作区每一层的 AGENTS.md / CLAUDE.md / AGENTS.local.md / CLAUDE.local.md。**只做查看、编辑、新建、停用启用与回收站，不做删除。**
  - 工具栏：只有主按钮「新建 AGENTS.md」与「⋯」（回收站、刷新）。没有搜索与筛选——文件本来就只有几个。
  - 列表两组：**全局**（标题行右侧「N 个」）与**当前工作区**（组内每行显示所在层：项目根标「项目根」、工作区标「当前工作区」）。没有工作区时这一组只有一行说明（照技能页的口气）。
  - 行 = 文件名 + 等宽副标题（层 · 大小 · 状态）+ 行尾开关（**停用 = 关**）。副标题按需追加：`已停用`、`与 AGENTS.md 相同，DSH 只加载一份`、`超过 1 MiB，DSH 不加载`、`约 xx KB 超出预算，DSH 会省略 / 截断`。
  - 底部一行合计 `约 xx KB / 64 KB`（估算会加载的字节 / DSH 的预算，悬停说明预算从哪来）；当前 profile 里 DSH 的提示词加载被关掉时改成一句说明「当前 profile 里 DSH 的提示词加载已关闭」。
  - 详情抽屉：上面是完整路径与大小（等宽），正文是**等宽多行文本框**（可编辑，形态与 MCP 的 JSON 编辑一致）；底部「还原」（放弃未保存的改动，放最左）与「保存」（**有改动才可点**）。保存成功 Toast「已保存，旧内容已放进回收站」。
  - 冲突：文件被别处改过时宿主返回 409，正文里出现一条 danger 横幅「文件已在别处修改」+「重新加载」；冲突未解决前「保存」不可点（绝不用旧内容覆盖别人的改动）。
  - 新建 AGENTS.md：对话框里选位置——全局 / 项目根 / 当前工作区，**不可用的置灰并说明原因**（「这里已经有 AGENTS.md 了」/「没有当前会话工作区」）。只建 AGENTS.md。
  - 停用 / 启用：**原地改名**（`AGENTS.md` ↔ `AGENTS.md.disabled`），要先确认；**该文件所在的那一层**在 git 仓库里时（项目根命中 `projectRootMarkers`，默认 `.git`）确认框里多一句「这个目录在 git 仓库里，git 会显示文件被改名」。全局层的文件在 DSH 主目录里、不属于任何项目，**不会**有这一句。停用的文件照常列出，行上标「已停用」。
  - 回收站抽屉：列出旧版本（路径、原因 · 时间 · 大小），每项悬停「恢复 / 彻底删除」，底部「清空」（RiskConfirmation）。恢复要先确认——当前内容也会进回收站。
